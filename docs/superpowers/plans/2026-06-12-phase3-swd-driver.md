# debugprobe-zephyr Phase 3 (SWD Driver) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `NullSwdDriver` with a real SWD driver so the firmware can actually debug a target: a thin `dap::SwdDriver` adapter over Zephyr's `swdp_api`, backed first by the upstream proven `zephyr,swdp-gpio` bitbang driver (3a) and then by a custom PIO driver `drivers/dp_pio/` ported from the original `probe.pio`/`probe_oen.pio` + `sw_dp_pio.c` for performance parity (3b).

**Architecture:** Both backends implement the same Zephyr `swdp_api` (`include/zephyr/drivers/swdp.h`), so a single `ZephyrSwdpDriver` adapter — mapping `dap::SwdDriver` calls 1:1 onto `swdp_api` — works over either. The firmware selects the backend purely by devicetree (which `swdp` node carries the `swd_dev` nodelabel), no C changes. The `dap::SwdDriver`/`DapEngine` contract from phase 2 is unchanged.

**Tech Stack:** Zephyr 4.4.0 + pico-sdk PIO HAL (`hardware/pio.h` via `pio_rpi_pico` misc driver), pioasm (host tool in `modules/hal/rpi_pico/tools/pioasm`), C (Zephyr driver) + C++20 (adapter). Reference firmware: `~/Developer/debugprobe/src/{probe.c,sw_dp_pio.c,probe.pio,probe_oen.pio}` and `include/board_*_config.h`.

## swdp_api ↔ dap::SwdDriver mapping (the whole of 3a)

Zephyr `swdp_api` (`include/zephyr/drivers/swdp.h`):

| swdp_api method | dap::SwdDriver call | Notes |
|---|---|---|
| `swdp_output_sequence(dev, count, data)` | `swj_sequence(data, count)` **and** `swd_output(data, count)` | clock out `count` bits LSB-first |
| `swdp_input_sequence(dev, count, data)` | `swd_input(data, count)` | capture `count` bits |
| `swdp_transfer(dev, request, *data, idle_cycles, *response)` | `transfer(request, data)` | idle_cycles from the adapter's stored value; ACK → `*response` |
| `swdp_set_pins(dev, pins, value)` | part of `set_pins(select, value, wait_us)` | then busy-wait, then get_pins |
| `swdp_get_pins(dev, *state)` | `read_pins()` | |
| `swdp_set_clock(dev, clock)` | `set_clock(hz)` | |
| `swdp_configure(dev, turnaround, data_phase)` | `configure(turnaround, data_phase)` | |
| `swdp_port_on(dev)` / `swdp_port_off(dev)` | `connect()` / `disconnect()` | |

ACK values are identical across both worlds: `SWDP_ACK_OK=BIT(0)=1`, `WAIT=BIT(1)=2`, `FAULT=BIT(2)=4`, `SWDP_TRANSFER_ERROR=BIT(3)=8` — equal to `dap::kXferOk/Wait/Fault/ProtocolError`. So `transfer()` returns `static_cast<dap::Ack>(response_byte)`; a driver-level error (negative return) maps to `dap::Ack::ProtocolError`.

- [ ] **Step 1: Write `src/dap/swdp_driver.hpp`**

```cpp
#pragma once
/* Adapts a Zephyr swdp_api device (bitbang or PIO) to dap::SwdDriver,
 * so the phase-2 DapEngine drives real hardware. Backend is chosen by
 * devicetree (the node carrying the `swd_dev` nodelabel).
 */
#include <zephyr/device.h>

#include "dap/interfaces.hpp"

namespace probe {

class ZephyrSwdpDriver final : public dap::SwdDriver {
public:
	explicit ZephyrSwdpDriver(const struct device *dev) : dev_(dev) {}

	bool ready() const;

	void set_clock(uint32_t hz) override;
	void connect() override;
	void disconnect() override;
	void configure(uint8_t turnaround_cycles, bool data_phase) override;
	void set_idle_cycles(uint8_t cycles) override { idle_cycles_ = cycles; }
	void swj_sequence(std::span<const uint8_t> data, size_t bit_count) override;
	void swd_output(std::span<const uint8_t> data, size_t bit_count) override;
	void swd_input(std::span<uint8_t> data, size_t bit_count) override;
	dap::Ack transfer(uint8_t request, uint32_t *data) override;
	void set_pins(uint8_t select, uint8_t value, uint32_t wait_us) override;
	uint8_t read_pins() override;
	void delay_us(uint32_t us) override;
	uint32_t timestamp() override;

private:
	const struct device *dev_;
	uint8_t idle_cycles_ = 0;
};

} // namespace probe
```

- [ ] **Step 2: Write `src/dap/swdp_driver.cpp`**

```cpp
#include "dap/swdp_driver.hpp"

#include <zephyr/drivers/swdp.h>
#include <zephyr/kernel.h>
#include <zephyr/logging/log.h>

LOG_MODULE_REGISTER(swdp_drv, LOG_LEVEL_INF);

namespace probe {

namespace {
const struct swdp_api *api(const struct device *dev)
{
	return static_cast<const struct swdp_api *>(dev->api);
}
} // namespace

bool ZephyrSwdpDriver::ready() const
{
	return device_is_ready(dev_);
}

void ZephyrSwdpDriver::set_clock(uint32_t hz)
{
	api(dev_)->swdp_set_clock(dev_, hz);
}

void ZephyrSwdpDriver::connect()
{
	api(dev_)->swdp_port_on(dev_);
}

void ZephyrSwdpDriver::disconnect()
{
	api(dev_)->swdp_port_off(dev_);
}

void ZephyrSwdpDriver::configure(uint8_t turnaround_cycles, bool data_phase)
{
	/* swdp_configure takes turnaround as a 1-based cycle count and a
	 * data-phase flag, matching DAP_SWD_Configure semantics. */
	api(dev_)->swdp_configure(dev_, turnaround_cycles, data_phase ? 1U : 0U);
}

void ZephyrSwdpDriver::swj_sequence(std::span<const uint8_t> data, size_t bit_count)
{
	api(dev_)->swdp_output_sequence(dev_, static_cast<uint32_t>(bit_count),
					data.data());
}

void ZephyrSwdpDriver::swd_output(std::span<const uint8_t> data, size_t bit_count)
{
	api(dev_)->swdp_output_sequence(dev_, static_cast<uint32_t>(bit_count),
					data.data());
}

void ZephyrSwdpDriver::swd_input(std::span<uint8_t> data, size_t bit_count)
{
	api(dev_)->swdp_input_sequence(dev_, static_cast<uint32_t>(bit_count),
				       data.data());
}

dap::Ack ZephyrSwdpDriver::transfer(uint8_t request, uint32_t *data)
{
	uint8_t response = 0;
	uint32_t scratch = 0;
	int ret = api(dev_)->swdp_transfer(dev_, request,
					   data ? data : &scratch,
					   idle_cycles_, &response);
	if (ret < 0) {
		return dap::Ack::ProtocolError;
	}
	return static_cast<dap::Ack>(response);
}

void ZephyrSwdpDriver::set_pins(uint8_t select, uint8_t value, uint32_t wait_us)
{
	api(dev_)->swdp_set_pins(dev_, select, value);
	if (wait_us != 0U) {
		k_busy_wait(wait_us);
	}
}

uint8_t ZephyrSwdpDriver::read_pins()
{
	uint8_t state = 0;
	api(dev_)->swdp_get_pins(dev_, &state);
	return state;
}

void ZephyrSwdpDriver::delay_us(uint32_t us)
{
	k_busy_wait(us);
}

uint32_t ZephyrSwdpDriver::timestamp()
{
	return k_cyc_to_us_floor32(k_cycle_get_32());
}

} // namespace probe
```

Verify the exact `swdp_api` member names and `swdp_transfer`/`swdp_configure` signatures against `~/Developer/zephyrproject/zephyr/include/zephyr/drivers/swdp.h` before building; adapt minimally if they differ and record it.

### Task 4: PIO SWD driver implementing `swdp_api` (3b core)

**Files:**

This is a faithful port of `~/Developer/debugprobe/src/probe.c` (PIO primitives) and `sw_dp_pio.c` (SWD protocol). Read BOTH fully before writing. No host test exists; the review gate is line-by-line parity with the references + a clean three-board build.

**The PIO command FIFO format** (`probe.c:98-105` `fmt_probe_command`): each command word is
`((bit_count - 1) & 0xFF) | ((out_en ? 1 : 0) << 8) | (cmd_addr << 9)`
where `cmd_addr` is `pio_offset + probe_offset_{write_cmd | get_next_cmd | turnaround_cmd | read_cmd}`. `CMD_SKIP` uses `get_next_cmd`. Write commands are followed by a data word; read commands return a pushed word; turnaround/skip are followed by a 0 data word.

**Primitives to port** (`probe.c:107-148`):
- `probe_write_bits(n, data)`: put write-cmd(out_en=1, n), put data.
- `probe_read_bits(n) -> uint32`: put read-cmd(out_en=0, n), `pio_sm_get_blocking` → data (LSB-aligned).
- `probe_hiz_clocks(n)`: put turnaround-cmd(out_en=0, n), put 0.
- direction skips (`probe_skip_*`, `probe.c:142-148`): put skip-cmd with out_en 0/1 to flip SWDIO pindir without clocking.

**Clock divider** (`probe.c:61-72` `probe_set_swclk_freq`):
`divider = (((clk_sys_khz + freq_khz - 1) / freq_khz) + 3) / 4`, clamp to `[1, 65535]`, then `pio_sm_set_clkdiv_int_frac(pio, sm, divider, 0)`. `clk_sys_khz` = `sys_clock_hw_cycles_per_sec()/1000` (Zephyr) — confirm RP2040/RP2350 report the PIO clock here; if not, read it from the `clocks` DT/`clock_control` API and record.

**SWD_Transfer** (`sw_dp_pio.c:110-208`) — port exactly, including:
- request packet build (start=1, 4 addr bits from `request`, parity, stop=0, park=1), `probe_write_bits(8, prq)`.
- ACK = `probe_read_bits(turnaround + 3) >> turnaround`.
- OK + read: `probe_read_bits(32)` + parity bit, parity check → `SWDP_TRANSFER_ERROR` on mismatch, `*data = val`, `probe_hiz_clocks(turnaround)`.
- OK + write: `probe_hiz_clocks(turnaround)`, `probe_write_bits(32, val)`, parity bit.
- idle cycles after OK (drive 0 for `idle_cycles` clocks, 256 at a time) — use the `idle_cycles` ARG of `swdp_transfer`, not a global.
- WAIT/FAULT: data-phase dummy read(33)/write(32+1) per `swd_conf.data_phase`, `probe_hiz_clocks(turnaround)`.
- protocol error: `probe_read_bits(turnaround + 32 + 1)`.
- return the ACK byte into `*response`, return 0.

**SWJ_Sequence** (`sw_dp_pio.c:42-66`) → `swdp_output_sequence`: clock out `count` bits from `data`, 8 (or remaining) bits per `probe_write_bits`.

**SWD_Sequence input** (`sw_dp_pio.c:69-108`) → `swdp_input_sequence`: capture `count` bits via `probe_read_bits`, packing into `data`.

**port_on / port_off** (`probe.c:151-180` `probe_init`/`probe_deinit`): claim an SM (`pio_rpi_pico_allocate_sm`), `pio_add_program`, configure the SM (side-set = SWCLK, out/set/in pins = SWDIO, shift dirs both right/LSB-first, autopull/push off — mirror `probe_sm_init` in the .pio c-sdk block you stripped), `pio_sm_init`, exec `get_next_cmd`, enable; default clock 1 MHz. port_off disables the SM and asserts nRESET.

## Known Risks and Handling

- **PIO timing unverifiable without hardware**: mitigated by pioasm-reproducible opcodes (Task 3 gate) + line-by-line port parity (Task 4 gate) + the proven bitbang fallback. The honest residual risk (edge alignment, divider rounding, SM config) is documented in `HARDWARE_BRINGUP.md` and surfaces only on real hardware.
- **`pio_rpi_pico` / pico-sdk PIO HAL availability**: the misc PIO driver (`CONFIG_PICO_PIO_RPI_PICO`) and `hardware/pio.h` must be enabled/visible; if the firmware build can't resolve `pio_sm_*`, enable the misc driver and confirm the hal_rpi_pico module include path (Task 4 Step 5).
- **Out-of-tree driver glue**: app-local `drivers/dp_pio/` may need module wiring (`zephyr/module.yml` + `ZEPHYR_EXTRA_MODULES`) rather than a bare `add_subdirectory`; Task 4 Step 4 allows either — use whatever builds and record it.
- **`swdp_api` signature drift vs Zephyr 4.4**: verify member names/signatures in `include/zephyr/drivers/swdp.h` before writing the adapter and the driver (Task 1/Task 4); the bitbang driver `drivers/dp/swdp_bitbang.c` is the authoritative example of a correct `swdp_api` implementation.
- **Debug Probe buffered pins (OEn/SWDI)**: the `probe_oen` program + separate input pin path is the least-tested; re-verify pin numbers against `board_debug_probe_config.h` (Task 5 Step 1) and treat the Debug Probe PIO path as the highest-risk item for hardware bring-up.
